## Root-cause brief (om-root-cause, passed verbatim to om-fix)
Summary: Files browsing can disclose replacement content after validating an earlier file.

Root cause: readWorktreePath performs lstat at git-changes.ts:709 and realpath containment checks, then sniffBinary opens target at :672 and readFile opens it again at :758. A replacement between those operations can bypass the earlier identity/containment checks. Inferred from source; deterministic regression follows during implementation.

Files to change:
- packages/cezar/src/server/git-changes.ts — open once and bind inspection/read to the checked regular file identity.
- packages/cezar/src/server/git-changes-race.test.ts — deterministic leaf/ancestor replacement, between-sniff/read redirection, closure and compatibility cases using real temporary files.

Approach: Open the resolved target with read-only, no-follow and nonblocking flags where available. Compare descriptor device/inode with the original lstat and require a regular file before reading; sniff and read through that same handle, closing in finally. Test swaps before and after opening, including an ancestor symlink, and run existing browsing tests. Preserve zero-config behavior and HTTP response shapes.

Risks: O_NOFOLLOW alone does not protect ancestors; inode comparison is required. Same-inode concurrent writes/hardlinks are not a full same-user sandbox. Windows lacks O_NOFOLLOW, so identity comparison remains mandatory. Preserve directory behavior and binary/size-cap metadata; opened handles must close on rejection and errors.
