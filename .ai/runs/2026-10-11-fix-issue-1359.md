# Keep explicit graph commits clean up and release run-scoped check state

Issue: #1359

## Goal

Prevent explicit graph `git.commit` nodes from committing unchanged check-generated residue, while releasing check-artifact ownership state when a run can no longer be continued.

## Scope

- `packages/cezar/src/git-worktree.ts`: allow explicit commits to apply the same content-owned exclusions as autosaves.
- `packages/cezar/src/workflows/run.ts`: thread current exclusions through the graph commit node and clear both run-scoped check maps at permanent terminal settlement.
- Focused git/workflow tests covering tracked and untracked residue, later agent edits, parked continuation retention, and terminal cleanup.

## Non-goals

- Do not change the existing autosave/check capture contract from PR #1126.
- Do not delete check artifacts from disk; explicit commits should leave excluded artifacts dirty for inspection.
- Do not prune state merely because `dropActive` runs: parked continuations and restart recovery still need their snapshots.
- Do not alter unrelated graph, worktree retention, or UI behavior.

## Risks

The cleanup boundary must not be confused with `dropActive`: `failed` runs may be continued, while `done`, `review`, and `cancelled` are permanent only once their lifecycle has actually settled. The implementation will follow the existing continuation eligibility and terminal settlement paths rather than infer permanence from registry membership alone.
