# Run: bigger README hero, black brand icon

## Goal

Follow-up to #1130. Two asks from the report on the merged result: the hero icon should be
the black tile with the white mark rather than the violet one, and the headline and
description should be bigger than they ended up after the headings were removed.

## Context

#1130 removed the hero's decorative headings because GitHub appends a permalink anchor —
the chain octicon, permanently visible on touch devices — to every heading element, raw
HTML included. That fixed the icons but dropped the hero text to body size, since the
headings were also what made it big.

Two probe commits on the previous branch, rendered through the contents endpoint with the
HTML media type, established what GitHub actually allows:

| markup | rendered as |
| --- | --- |
| `<font size="6">` | tag stripped, text left at body size |
| `<span style="font-size: 32px">` | `style` attribute stripped |
| `<big>` | tag stripped |
| heading in a table cell / blockquote / `<details>` | still wrapped + anchored |
| heading with an explicit `id` | still anchored (its own generated id) |
| heading containing only an `<img>` | still anchored, with a **broken** `id=""` / `href="#"` |
| `<picture>` + `prefers-color-scheme` source | survives, wrapped in `<themed-picture>` |

So GitHub offers exactly one way to enlarge text — a heading — and a heading always carries
the icon. Bigger hero text therefore has to be drawn, and the drawing has to be theme-aware,
which `<picture>` supports.

The icon question needs no judgement: `docs/brand/README.md` lists
`cezar-icon-black.svg` (black tile, white mark, 21:1) as the "main icon: app, favicon,
avatars, GitHub", and the violet one as an avatar/social variant.

## Scope

- `README.md`, `README.zh-CN.md`, `README.zh-TW.md` — hero block only.
- `scripts/build-readme-hero.mjs` — generates `docs/hero/hero-{lang}-{light,dark}.svg`.
  The copy lives in the script, every line's width is measured from a font-metrics table
  and pinned with `textLength`, and the script fails if a line exceeds the box.
- Box width is 380 px so the image barely scales down in GitHub's ~330 px mobile column:
  the headline lands at ≈26 px and the description at ≈19 px there, against 16 px body
  text, and at 30/22 px on desktop — roughly the `<h1>`/`<h2>` sizes the hero had before.

## Non-goals

- No changes to section headings or their anchors.
- No new *logo* assets — brand logo files come from one script in another repository. The
  hero SVGs are typographic README assets generated by their own script here.
- No copy rewrites: the headline and description are the existing words, moved into the
  image and repeated verbatim in its `alt`.

## Risks

- **Hero text as an image loses live text**: no selection, no in-browser translation of
  those two sentences, no indexing beyond the `alt`. The rest of the README stays real
  text. This is the price of "bigger" and is called out on the PR so it can be reverted
  on its own.
- **Nobody has seen it**: this machine has no browser, no SVG rasteriser and no system
  fonts. Mitigated by pinning every line with `textLength` (identical layout on any
  device, whichever font it picks) and asserting line widths, but aesthetics need a human
  eye — hence `needs-qa`.
- npm sanitizes README HTML harder than GitHub and may drop `<picture>`/`<source>`,
  leaving the light `<img>` fallback. That is the correct degradation, not a defect.
