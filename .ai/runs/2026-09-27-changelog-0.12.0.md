# Release 0.12.0 — complete the changelog entry and stamp the release set

Status: complete

## Goal

Make `CHANGELOG.md`'s 0.12.0 entry describe everything merged into `main` since
`v0.11.1`, and stamp the release set at 0.12.0.

## Scope

- `CHANGELOG.md` — the 0.12.0 entry, extended from 11 bullets to 34.
- The five versioned manifests (`contract`, `api-client`, `cezar`, `web`,
  `alias-cezar`) plus `package-lock.json` — `0.11.1` → `0.12.0`, and the
  intra-release `^0.11.1` ranges → `^0.12.0`.
- `SECURITY.md` — the supported-version table, which names the latest minor
  line and would otherwise declare the new release unsupported.

### Non-goals

- ~~The `## Highlights` paragraph.~~ Originally a non-goal, since the skill
  forbids fabricating it. The maintainer then delegated it explicitly, so it is
  written in Phase 4 and still wants their read for voice.
- Tagging or publishing. This PR only stamps the version; cutting `v0.12.0` and
  publishing to npm stay with the maintainer.
- Any behavior change. No source file is touched.

## Window

Reachability mode, per `om-auto-update-changelog`'s `references/release-window.md`:

```
git log --first-parent v0.11.1..origin/main   ->  35 PRs
```

Cross-checked against `gh pr list --state merged` for `merged:>=2026-09-17`;
the only extras were 0.11.1's own PRs and the #1023 release bump, so the
reachable set is complete and nothing was silently truncated.

`#1083` is excluded — it is the prior run of this skill (the partial 0.12.0
draft this PR completes). That leaves 34 bullets: the 11 already in the entry
plus 23 new ones.

## Credit verification

All 23 new credits were compared against each PR's commit authorship:

- No credited author wrote zero commits, so no Path D umbrella merge and no
  Path E prose hand-off.
- No `Supersedes` / `Credit: original implementation by` template matched, and
  the Path C sweep of the window's closed-unmerged PRs found no
  `Closing in favor of` trail. Every bullet therefore credits its PR author.
- `claude` and `cursoragent` co-authorship is excluded per the never-credited
  rule; `@matgren` and `@tayfuryldz` are new to the entry's contributor block.

One categorization departs from the label-derived default, deliberately: #1006
carries a `bug` label but its own body states the production fix shipped in
#928 (released in 0.11.0) and this PR adds only the end-to-end regression test.
Filing it under Fixes would tell a reader a bug was fixed in 0.12.0. It sits in
a new `## 🧪 Testing` section with #1097, the other test-only PR.

## Risks

- **Low.** No source file changes. The version bump's blast radius is the
  packaged tarball, which `build` and `test:package` cover.
- A stale `SECURITY.md` table is the one correctness trap in a release bump; it
  is handled in the same commit as the bump.
