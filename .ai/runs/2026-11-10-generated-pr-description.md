# Generated PR title and description (#1757)

Source doc: GitHub issue #1757

## Goal

Publishing a task from the cockpit's server path opens a PR with a conventional title and a structured description (Summary / Changes / Verification / Changelog) generated by a one-shot turn on the run's own backend — editable before `gh pr create`, cost recorded on the run, and falling back to today's `run.title` + `buildPrBody` on any failure, timeout or `CEZ_DRY_RUN=1`.

## Scope

- `packages/cezar/src/server/pr-description.ts`: prompt, strict-JSON parse, body composition, the bounded one-shot runner call.
- Contract: `createPrRequestSchema` (`draft?`, `title?`, `body?`) moved into `packages/contract`; new `prDraftResponseSchema`.
- Route `POST /runs/:id/pr/draft` (preview, records cost); `POST /runs/:id/pr` honours `title`/`body`; `createDraftPr` takes optional overrides.
- Cockpit: a `PrDialog` for the server Create PR path — loads the draft, editable title/body, then publishes.
- `CEZ_PR_DESCRIBE=0` off switch: `.env.example`, `docs/reference.md`, AGENTS.md exception line, docs feature page.

## Non-goals

- Filling a repo's `.github/pull_request_template.md` (fixed sections for now).
- The agent-prompt Create PR path (the agent writes its own PR) and the graph `github.draft-pr` node — unchanged.
- `POST /pr` without `title`/`body` behaves exactly as today.

## Risks

- Default-on model spend (bounded: one call per dialog open, short timeout) — recorded as pending owner ratification in AGENTS.md.
- A runner that ignores `allowedTools` (Codex) could act; the prompt carries the diff so no tools are needed.
