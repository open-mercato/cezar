# Junie CLI backend

## Goal

Run JetBrains Junie through cezar's shared runner, workflow, account, composer,
and review-gate seams. The integration must be zero-config: a missing Junie
binary or unavailable credentials must not prevent cezar from booting.

## Design

- Register `junie` across backend/provider identities, model settings, profiles,
  API unions, automation prompts, account defaults, and thread attribution.
- Spawn `junie --acp=true -p <cwd>` through the credential-filtered child
  environment. `CEZ_JUNIE_BIN` overrides discovery and `CEZ_DRY_RUN=1` uses the
  bundled ACP mock.
- Initialize ACP, authenticate, create or resume a session, enable `brave_mode`,
  and apply an explicit model through `session/set_config_option`.
- Map ACP text, images, tool calls/results, edits, messages, usage, costs,
  failures, cancellation, and shutdown into both v1 agent events and immutable
  v2 UI events. Queue follow-ups in the same process and prevent queued work
  from starting after session close.
- Verify credentials through bounded ACP model discovery: initialize and
  authenticate, then open a short-lived session to read `session/new` model
  config options. Report the provider as connected only when at least one model
  is returned; never submit a prompt. Runtime authentication failures use the
  existing provider recovery path.
- `end()` closes stdin and escalates SIGTERM to SIGKILL. Interrupt sends ACP
  cancellation and terminates the child; exit rejects pending RPCs, including
  startup, so a dead process cannot hold a run slot.
- Support CLI takeover with `junie --resume --session-id=<validated id>`.

## Behavior and limits

Junie uses its own login and default model unless the user selects one. Full-auto
permissions match existing backend policy; Junie does not expose per-tool
allowlists. The ACP capture had no structured plan, reasoning, or child-session
attribution, so those are mapped only when standard ACP updates provide them.

## Evidence

The authenticated Junie 26.9.22 ACP capture and initial investigation are
recorded in run `fc9ad513-6de7-42c0-ac58-37966e36b33e`. Golden fixtures live in
`packages/cezar/src/core/__fixtures__/junie/`; the runner and mapper tests cover
normal lifecycle, tool lifecycle, cancellation, malformed input, and startup
failure. Fixture comments distinguish observed wire messages from standardized
ACP variants not observed in the capture.

## Validation

- `npm run typecheck` passed across all four workspaces.
- Junie runner and mapper focused tests passed, including the committed golden
  fixture replay and cancellation cases.
- `git diff --check` passed.
- The earlier broad run reported 8,284 passing tests and 19 unrelated failures;
  the full suite is not claimed green. The known failures were documented rather
  than hidden: a truncated UI event expectation, a worktree-local Vitest binary
  lookup, and a system-prompt timeout.
