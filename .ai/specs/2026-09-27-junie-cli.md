# Junie CLI backend

## Goal

Run JetBrains Junie through cezar's shared runner, workflow, account, composer,
and review-gate seams. The integration must be zero-config: a missing Junie
binary or unavailable credentials must not prevent cezar from booting.

## Design

- Register `junie` across backend/provider identities, model settings, profiles,
  API unions, automation prompts, account defaults, and thread attribution.
- Spawn `junie --acp=true -p <cwd>` through the credential-filtered child
  environment. `CEZ_JUNIE_BIN` overrides discovery and `CEZ_DRY_RUN=1` uses the
  bundled ACP mock.
- Initialize ACP, authenticate, create or resume a session, enable `brave_mode`,
  and apply an explicit model through `session/set_config_option`.
- Map ACP text, images, tool calls/results, edits, messages, usage, costs,
  failures, cancellation, and shutdown into both v1 agent events and immutable
  v2 UI events. Queue follow-ups in the same process and prevent queued work
  from starting after session close.
- Verify credentials through bounded ACP model discovery: initialize and
  authenticate, then open a short-lived session to read `session/new` model
  config options. Report the provider as connected only when at least one model
  is returned; never submit a prompt. Runtime authentication failures use the
  existing provider recovery path.
- `end()` closes stdin and escalates SIGTERM to SIGKILL. Interrupt sends ACP
  cancellation and terminates the child; exit rejects pending RPCs, including
  startup, so a dead process cannot hold a run slot.
- Support CLI takeover with `junie --resume --session-id=<validated id>`, matching the
  verbatim, no-quoting-in-any-shell splice every other backend's `resumeCommand` case uses
  (#431). Verified live against `junie --help` (26.9.22): `--resume` alone reopens the LAST
  session; `--session-id=<id>` (or a `junie://sessions/<id>` link) is the separate flag that
  names which one — junie's positional argument slot is `[<task>]`, so a bare
  `junie --resume <id>` (the shape this PR originally shipped, caught in review) would silently
  resume the wrong session and read the id as a task prompt instead.

## Behavior and limits

Junie uses its own login and default model unless the user selects one. Full-auto
permissions match existing backend policy; Junie does not expose per-tool
allowlists. The ACP capture had no structured plan, reasoning, or child-session
attribution, so those are mapped only when standard ACP updates provide them.

## B2 follow-up (review om-auto-review-pr, PR #1111)

The review flagged `ui-parity.test.ts`'s generic `exempt?` mechanism as a regression against
`BACKWARD_COMPATIBILITY.md` §7 / `AGENT_PROTOCOL.md` §6's hard parity rule, and asked for a human
call rather than picking one of its two suggested routes itself. Resolved: schema-derived fixtures.

- `plan.updated`/reasoning are no longer exempted — `__fixtures__/junie/schema-plan-reasoning.*`
  implements both per the public ACP schema (agentclientprotocol.com) and is explicitly labelled
  as schema-derived rather than captured, exercising the mapper code that was previously
  dead-until-proven. Every backend, junie included, is now required to produce these two rows.
- "sub-agent task items" (and its nesting cell) cannot be satisfied by any fixture, real or
  schema-derived: junie's wire is unmodified core ACP, which has no `task` tool-call kind and no
  published `nativeSubagentSessions` shape at all — a genuine gap in the upstream protocol, not an
  assumption or a missing fixture. A drafted amendment to `AGENT_PROTOCOL.md` / `BACKWARD_COMPATIBILITY.md`
  was reverted (protected surfaces need a maintainer's sign-off). The third re-review then
  corrected its own earlier B2: no amendment was ever needed. This is exactly
  `BACKWARD_COMPATIBILITY.md` §7's "provably cannot exist on that backend's own wire format", whose
  documented path is `AGENT_PROTOCOL.md` §6's cited, row-scoped `except` in `CAPABILITIES` — the
  mechanism already in `main` for cursor. The row is back in the table with `except: ['junie']`
  and the ACP citation inline; §6's nesting paragraph lists junie beside codex, cursor and pi (a
  factual listing update, not a rule change).
