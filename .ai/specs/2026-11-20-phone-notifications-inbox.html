Why the icon shows a "1" nobody can clear, the small fix, and a place to handle what the badge counts. Spec: .ai/specs/2026-11-20-phone-notifications-inbox.md. Nothing implemented yet — pick below.

1 · What the "1" is

The icon number is a stale snapshot kept on the phone. It is the sum of each computer's last-known count, written only by a relay push or by the Your cezars screen's probe. cezar never sends a push when the count goes down, and the app never removes a delivered notification. Right now this computer's real count is 3 (3 live questions, 0 approvals, no unread important messages) while the phone shows 1 — whatever the last push left there.

Fix first, small PR, no relay change: count what pushes (and allow 0, never send a 0 push) · refresh every cezar's count on app foreground and while a cezar page is open · remove that cezar's delivered notification at 0 · the cockpit inside the app reports its live count to the shell. The badge is then right whenever the app has been opened. Lowering it while the app stays closed needs the relay's kind: "count" push (spec § Relay change).

Handled anywhere — desktop, another phone, the agent, Older, expiry — the item leaves the list, counts republish, and a phone told a higher number gets a silent count push (relay change) that sets its badge and removes the delivered notification at 0.

What it does

  • Reached from a bottom-bar tab whose badge is the same number the icon gets from this computer; a push tap lands here.
  • Each row names its project or manager. Open goes to the task or chat; questions answer inline (chips for a CEZ:ASK card, a field for free text); approvals decide inline.
  • Mark all read clears only task notices and important messages. Questions and approvals need a decision and are never bulk-dismissed — dismissing a question tells the agent.
  • An empty list says so: "Nothing needs you on cezar." and the icon has no number from this computer.

4 · Variants

A · Web inbox per cezar

The inbox above, in the cockpit. One implementation serves the phone, the desktop and the notch. Shows one computer at a time.

Cost: web + server. Low.

B · Native cross-cezar inbox

An inbox in the app shell listing every computer's items together. Needs a new tunnel read per cezar on each open, written twice (Swift, Java), and every inline action re-implemented natively.

Cost: high; offline computers show stale rows.

C · A + native glue

The web inbox of A, plus count chips on Your cezars that open each computer's inbox, and the push tap landing there. Cross-computer at a glance; one inbox.

Cost: A + small native change on both platforms.

D · Now is the list recommended

No new tab. Now's existing Needs you section becomes the server list, with a From-managers group and a This project · All switch. Keep C's native chips for several computers.

Cost: about A's, with less new UI. See § 4b.

4b · Variant D — the Now tab as the one list

Today: Now is the project home and the first bottom-bar tab. It has Sign-in needed, Needs you, Running and Finished today. Its Needs you is built in the browser from this project's tasks only (question, review, budget, waiting, lifecycle, failed — now-model.ts) and shows no manager items. The Now tab has no count.

How it fits

  • Same page, same tab. Needs you stays on top of Now; Running and Finished today stay below. The Now tab (and Now in the desktop sidebar) gets the badge. No new navigation.
  • Task rows keep today's reasons and one action (Answer, Review changes, Resume, Reply, Retry), now read from the server list, so a row on Now is exactly a unit of the badge.
  • Manager items (questions, approvals, important messages) get a From managers group with inline Answer, Approve/Reject, Open chat and Mark read. It collapses after 3 rows.

Project scope vs managers

  • This project: this project's tasks, plus items from managers connected to it (connectedProjectIds).
  • All: every project's tasks grouped by project, plus every manager item, including managers with no project. Its count equals the icon's number for this cezar.
  • A push tap and the badge land on All; the switch remembers the last choice.

Several cezars

Each computer serves its own Now. The cross-computer view stays native: Your cezars count chips (from C) open that computer's Now on All. The icon is still the sum.

New tab?

Not needed. D drops the Needs-you tab and the desktop third entry. Questions and Approvals keep their pages as filtered views of the same list.

Kept on the computer: the relay never learns what a push is about.
  • The existing per-cezar Notify me row becomes a page; its switch stays at the top and still owns the push grant.
  • The relay carries no kind, so the choice is stored on the computer, per phone: its own route, GET/PUT /api/v1/workspace/phone/push/prefs, kept in devices.json: push kinds, icon kinds, quiet hours with the phone's IANA timeZone, and the push kinds the app understands (only a phone that declares count gets silent count pushes). Not on PUT /workspace/phone/push: that body is strict, so an older cezar would reject it and the phone would lose its grant. An older cezar answers the new route with 404, and the page then shows the defaults read-only.
  • "Count on the icon" defaults to the push kinds; turning it off shows the full list.
  • Quiet hours are server-side and cheap: attention pushes are held, one is sent at the end if anything still waits, and silent count pushes still go out.
  • Per-manager "Notify me when important" on the desktop stays and still gates important messages.
