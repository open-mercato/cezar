Managers change cezar through approval cards

Design page for 2026-11-20-manager-admin-actions.md. These are static mockups. Every card's rows are stamped by the server from the op's parameters, so the cockpit renders them generically: the same component on desktop, in Approvals and in CezarBot.

2Settled cards and automatic changes

After a decision a card becomes one line. An auto-approved change (phase 4) never asks: it lands as a notice with Undo, raises the unread dot, and sends no OS notification.

✓ Changed meblohand's default model to Sonnet 5.5 · approved by you on your phone · Undo · History
⚡ Paused automation Nightly triage · automatically · Undo · Why — Allowed: low-risk automation changes in my projects, asked in chat
↩ Undone: worktree retention back to 7 days

5How the manager finds out what it may do

$ cez-manager propose --help
Changes to cezar. Each one becomes a card the user approves.
Scout may propose: its projects' settings (meblohand, cezar). Workspace settings: no.

Project settings
  project-config.default-models   Default model per runner        medium
  project-config.default-runner   Default runner                  medium
  project-config.retention        Worktree retention and cleanup  medium
  project.tags                    Project tags                    low
Automations
  automation.pause                Pause an automation             low
  automation.delete               Delete (undo recreates it)      high, always asks
Worktrees
  worktrees.reclaim               Reclaim idle worktrees          medium
Needs the user (opens a screen)
  account.reconnect               Sign an account in again        handoff
