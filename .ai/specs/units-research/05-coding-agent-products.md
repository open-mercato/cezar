## 3. Findings — what leaders do that cezar doesn't, and what they deliberately don't do

**What leaders do that cezar (units) doesn't yet:**

- **Cross-vendor orchestration at the platform level.** GitHub Agent HQ runs Claude, Codex, and Copilot *side by side in the same repo* with automatic per-session worktrees and a single fleet view. This is the closest thing to cezar's own multi-backend pitch, but it's shipping from a platform with GitHub's distribution, not a local CLI — cezar's differentiation has to be "runs anywhere, no GitHub account or cloud dependency required," not "supports multiple backends" (that's no longer novel).
- **Per-role model selection as a first-class, advertised lever.** Factory Missions explicitly sells "pair a strong orchestrator with cheaper workers" as the headline cost story. Amp auto-selects models per subagent task. Claude Code users do this manually. Cezar's units spec doesn't surface per-rank model choice as a pitched feature (worth checking whether it's supported and, if so, marketing it).
- **A dedicated, product-named reviewer role with deliberately *withheld* context.** Devin Review is explicitly given no prior context from the authoring Devin — Cognition found this produces better review than a review pass that shares the author's reasoning. Cezar's spec (A5) already does something similar (a REVIEW unit judging a different unit's branch), which is good, but this is worth stress-testing: does cezar's reviewer see the commander's brief/plan? If yes, it may be sharing more context than the leader who studied this found useful.
- **Managed, paid, cloud review as its own SKU.** Anthropic's `/ultrareview` and GitHub's coding-agent review are sold and priced *separately* from the base agent — review is a distinct revenue line, not a free side effect of the workflow. Cezar's Guard/reviewer is bundled into the mission; there's no equivalent "buy one review pass" product framing (may not be desired, given cezar is local/BYO-model, but worth noting as a monetization pattern cezar forgoes by being infra, not a hosted service).
- **Published, if messy, per-task cost transparency (ACUs, credits).** Every commercial competitor has settled on *some* unit of billing (ACU, AI Credits, task-count quota) that a user can point to and complain about. Cezar's `resources.parallel`/`maxChildren` and per-child budget are correct primitives, but there's no comparison point yet for "how much does a mission cost" the way Devin's $2/ACU or Copilot's $0.01/credit exist as anchors — this is a gap only in that cezar has no marketing answer to "what will this cost me," even though the plumbing (real-cost charging in `remainingBudgetUsd`) is arguably more honest than ACUs.

**What leaders deliberately do NOT do, and why (the more important finding):**

- **Cognition (Devin) explicitly argues against generic multi-agent delegation.** Their blog "Don't Build Multi-Agents" (fetched directly) makes three concrete claims: (1) context partitioning causes subagents to build mutually incompatible pieces because they can't see each other's decisions; (2) "actions carry implicit decisions, and conflicting decisions carry bad results" — parallel agents on a shared goal silently diverge; (3) decision-making becomes too dispersed for the system to stay coherent. Their prescription: default to a **single-threaded linear agent**; only add a second agent (Devin Review) when the two roles benefit from a **fresh, un-shared context** — i.e., their one validated multi-agent pattern is authoring + independent reviewer, exactly cezar's REVIEW-unit pattern, not general commander/worker delegation trees. **This is a direct, credible critique of cezar's core premise** (a commander delegating to N workers) from the team most publicly identified with studying this failure mode. Cezar should have an explicit answer to "why does your hierarchy avoid the context-partitioning trap Cognition documented" — the mission directory (files as shared substrate, suggestions copied to root inbox) is a partial answer, but it's not obviously sufficient against "conflicting decisions carry bad results" when two workers edit adjacent code without seeing each other's in-flight choices.
- **Nobody publishes a true $-denominated mission/task budget with hard enforcement.** Every competitor uses either time-window quotas (Codex, Jules, Windsurf), credit pools (Copilot, Claude), or ACU pay-as-you-go with overages (Devin) — none of them let a user say "this mission may not spend more than $X" and have it hard-stop. This is the single clearest complaint pattern (see §5: Devin ACU overages, Claude Code subagent token burn). If cezar's per-mission/per-child budget already hard-enforces a dollar cap, **that is a real, defensible differentiator**, not a redundancy — worth confirming it's true and leading with it.
- **Nobody ships unlimited parallelism.** Every competitor caps parallel agents explicitly (Cursor: 8; Jules: 15–60 concurrent by tier; Codex: task-count/5hr window) — parallelism is uniformly treated as a resource to ration, consistent with cezar's `parallel`/`maxChildren` design, not a place cezar is behind.

## 4. Where cezar's mission feature is differentiated vs. redundant with what ships free elsewhere

**Likely differentiated:**
- **Fully local, filesystem-native mission channel** (`.ai/cezar/missions/<id>/` — brief/plan/order/notes/report/inbox as plain files) with no cloud dependency and no vendor lock to a single model provider. Every competitor's equivalent (Agent HQ, Factory Missions, Devin's ACU-billed cloud) either requires their cloud/platform or a specific vendor's hosted execution. If a user wants missions to work fully offline/local-first, cezar has no direct commercial peer for that combination in this survey.
- **Real per-child cost charging back to a mission budget** (`remainingBudgetUsd` charges a settled child its actual cost) — this is more precise than any published competitor mechanism found (ACUs are a proxy unit, not actual spend; Claude Code and Cursor bill against a plan pool with no mission-level accounting).
- **A reviewer role that only merges on `approve`**, gating the *commander's own* merge action, layered under the mission concept rather than sold as a separate managed product (`/ultrareview`, Bugbot) — this could be pitched as "review is not an upsell, it's how the mission works," a contrast to Anthropic's/Cursor's separately-priced review SKUs.

**Likely redundant with what ships free/standard elsewhere:**
- **Worktree-per-run isolation to avoid file collisions.** GitHub Agent HQ, Windsurf (Wave 13), and cezar's own base product all now do this as table stakes — not a units-specific differentiator, and Agent HQ in particular ships this for free across three vendors' agents already.
- **"Spawn a subagent with a cheaper model" as a concept.** Claude Code, Amp, and Factory Missions all already let a user or the system pick a cheaper model for a sub-task. Cezar's rank→role composition is a more structured version of the same idea, but the base capability (cheap workers under an expensive planner) is not new — the pitch has to be about cezar's execution (file-based coordination, hard budgets, local-first), not the existence of tiered delegation itself.
- **A named hierarchy (commander/manager/worker) with Roman-rank flavor.** Functionally this mirrors Factory's orchestrator/worker/validator naming closely enough that "we have named roles" is not itself a differentiator — the differentiator, if any, is in what the roles are *allowed and forced* to do (mission-scoped budgets, file-only messaging, escalation-one-rank-at-a-time), not that they're named.

## 5. User pain points found

- **Token/cost blowouts from subagents (Claude Code).** Reported: a subagent-heavy session accounted for 85% of one user's token bill; another user burned 50% of their weekly 5x limit in ~30 seconds via subagents; three subagents on one task can be ~4x the cost of single-threaded work because each subagent gets a fresh context window rather than inheriting the parent's. Root cause named repeatedly: no context inheritance + no default cost guardrail.
- **Devin ACU overage "surprise bills."** Most-cited complaint: the low headline price ($20/mo Core) masks ACU pay-as-you-go that pushes real spend to $300–500/mo; a single mid-complexity feature can burn 30–60 ACUs; ambiguous tasks burn ACUs exploring before doing useful work, with no user-facing $ cap.
- **Cursor multi-agent state corruption.** Cursor's own team confirmed (Mar 2026) three root causes of a bug class where parallel/background agents lose or overwrite work: "Agent Review conflict," "Cloud Sync conflict," "Format On Save conflict." One user reported losing four months of work to this class of bug. Separately, a forum-reported bug shows wrong merge-conflict detection specifically in multi-agent mode.
- **Context lost at every agent handoff (general, not vendor-specific).** One source notes explicitly: the agent that wrote code has no reasoning represented in the PR, the reviewer has no visibility into alternatives considered, and the merge system can't reason about semantic conflicts — i.e., the handoff-context-loss problem Cognition's "Don't Build Multi-Agents" post warns about is also observed empirically in shipped multi-agent products, not just theorized.

## 6. Implications for cezar's positioning

- **Lead with local-first + real-dollar budget enforcement**, not with "we have hierarchy/delegation" — every serious competitor now has some version of delegation or parallel agents; the differentiated claims are (a) it runs fully on your machine with no vendor's cloud in the loop, and (b) the budget is an actual dollar cap charged from real settled cost, not a proxy unit (ACU/credit) with overage risk — directly answering the #1 documented complaint (Devin ACU surprise bills, Claude Code subagent token burn).
- **Preempt the Cognition critique explicitly** in any positioning/spec copy: state plainly why cezar's mission directory (files as shared, durable, tool-agnostic state) avoids the "sub-agents have no context of each other's work" failure Cognition documented — e.g., point to the notes.md/inbox mechanism and the review-unit's deliberate context isolation as a considered design, not an oversight. Silence here invites a sharp, citable objection from anyone who's read the Cognition post (and it is widely cited — it showed up unprompted across multiple searches in this research).
- **Don't market "named ranks" or "cross-tool support" as the differentiator** — Factory already has orchestrator/worker/validator, GitHub Agent HQ already runs three vendors' agents side by side with automatic worktrees. Those are now baseline expectations, not wedge features.
- **Consider a "mission cost" anchor number** (e.g., "typical N-unit mission costs $X-$Y") the way Devin (ACU), Copilot (credits) and Anthropic (`/ultrareview` $5–20) all now do — cezar currently has the plumbing (real cost charge-back) but no published number to compete with those anchors in a user's head.

## 7. Confidence and gaps

- **Pricing figures**: medium confidence. Nearly all pricing data came from third-party SEO/aggregator blogs (eesel, CloudZero, usecarly, etc.), not primary vendor pricing pages fetched directly — these sites are frequently updated but can lag or round vendor changes. Treat as directionally correct, verify before quoting externally.
- **Factory Missions architecture**: low confidence on mechanism details (context-sharing model, whether there's a hard budget) — the primary landing page fetched had no technical detail; only the pricing/tier structure and the orchestrator/worker/validator naming are reasonably solid, sourced from the product page's own marketing copy.
- **Devin/Cognition philosophy section**: high confidence — fetched cognition.com's own blog post directly, quotes are primary-source.
- **Not covered / explicit gaps**: no dedicated pass was made on OpenAI Codex's or Google Jules' internal review/QA mechanisms beyond what surfaced incidentally; Windsurf's and Amp's budget-enforcement mechanics (if any beyond quotas/PAYG) were not found and may simply not exist as advertised features; no primary Reddit/HN thread URLs were fetched directly (search snippets only) — pain-point claims in §5 are as reported by secondary sources aggregating that discussion, not verified against the original threads.
- **Time-boxing**: research was capped at ~18 searches/fetches per instructions; several products (OpenHands, Amp, Windsurf) got a single search pass each and could bear deeper investigation, especially around whether any of them enforce a true dollar-denominated mission budget (this survey's single most important comparison point for cezar) — none was found to do so, but absence of evidence in a capped search is not proof of absence.
