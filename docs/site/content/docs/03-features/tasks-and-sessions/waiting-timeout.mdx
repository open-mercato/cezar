Waiting-session idle timeout sets how many inactive minutes Cezar waits before closing a waiting backend session to free its resources. Nothing about the task changes: you can write to it at any time, and your message reopens the session.

## Where to find it

Settings → Global → Resources → Waiting-session idle timeout

## How to use it

1. Set the number of minutes.
2. Choose 0 to keep the session open without a time limit.
3. Write to the task as usual, from its composer or through a manager. The message reopens the closed session.

## What a closed task looks like

Closing an idle session is housekeeping, not a state change. The task keeps the state it had before: a task waiting for you still shows **needs you**, its thread still ends on the agent's last message, and the composer stays the ordinary one. Cezar does not mark it failed or closed, does not send a notification, and does not tell a manager about it. A task waiting on an answer to an agent's question keeps that question too.

Tasks dispatched by another task are the exception: their session still settles when it closes, so the parent receives a report. Tasks closed by an older version of Cezar show a neutral **idle** mark.

> **Good to know**: Sessions marked as monitoring are exempt from this timeout.

## A turn that goes silent

This timeout only covers a session that is waiting between turns. A turn that is still in flight but silent has its own bound, on by default and not configurable: after 45 minutes with no agent output (4 hours while the backend reports a tool as running) the task is parked as needing you and releases its slot. The session stays open. Any new output from the agent, or a message from you, makes the task active again; Cancel stops it.
