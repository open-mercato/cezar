CezarBot, the mobile app, connects to a cezar you host and shows that server's own cockpit, starting on Manager. It keeps your login in the phone's secure storage and can hold several servers. It is not in any store yet, so you build it yourself. Agents never run on the phone.

## Where to find it

`packages/mobile` in the cezar repository. The README there has the build steps.

## How to use it

1. Build the debug app and install it on your phone.
2. Enter your server's `https://` address.
3. If the server has a Basic login, enter the username and password. The app saves them only after the server accepts them.
4. The app reopens your last server on launch. The **Devices** list appears when that server cannot be reached. **Forget** there deletes that server's password and website data from the phone.

## Opening Manager

After connecting your computer, the app opens Manager when a coding agent is signed in and enabled. If none is ready, you see agent setup first. Manager opens as soon as setup succeeds; you do not need to add a Git project first. **Continue anyway** lets you browse before completing setup.

The same default applies on later launches and existing installs. Opening a task or Settings link keeps that destination. Reloading or reconnecting keeps the current page, and the Tasks button still opens your tasks.

## Navigation in smaller windows

Below 1024 pixels of available cockpit width, desktop browsers and tablets use the same bottom navigation as phones. It offers Now, Tasks, New task, Manager and More. Widening the window restores the desktop sidebar and closes an open navigation drawer. A cockpit inside a narrow container follows its container width.

The native app keeps the bottom navigation at every width. Settings has its own navigation, and the bottom bar hides while the on-screen keyboard is open.

## Switching devices

Your computer's avatar sits in the cockpit's header: a circle with its initials, in a colour picked from its name. On a wide screen the sidebar's top shows it with the computer's name. Tap it and the app shows a plain list of your computers, like an account switcher: each with its avatar, its name, a word for its state (Online, Offline since 14:02, Email not confirmed, Suspended) and how many tasks need you there, with a tick on the current one. Tap another computer to open it. **Add a device** and **Manage devices** are at the bottom. The list stays in the app: the cockpit page never learns about your other computers.

A notification names the computer that needs you, and tapping it opens that computer. The app icon's badge shows the total across your computers.

The server must run in hosted mode. Links that leave your server open in the system browser.

> **Good to know**: Plain `http://` is refused. Without a public server, reach cezar over HTTPS through ngrok, a Cloudflare Tunnel or `tailscale serve`. A temporary `trycloudflare.com` tunnel loads the cockpit, but live updates do not arrive through it. Both apps build in CI, and test builds go out through TestFlight and Google Play internal testing.

## App lock

**Turn on app lock** on the **Devices** list asks for your fingerprint, face or screen lock (Face ID, Touch ID or the passcode on an iPhone) each time the app starts and after a minute in the background. It is off by default and needs a screen lock on the phone. It only hides the app: anyone who knows the phone's screen lock can open it, and your login is stored the same way with the lock on or off. The iOS lock has not run on a phone yet.

## Reloading after a cezar update

**cezar was updated. This page is from the previous version.** means the cockpit open on your phone comes from a different build than the computer's running server. Tap **Reload** to check that the computer can serve the updated cockpit, then reload the current page. Your selected server, pairing and login stay in place. While the check runs, the button shows **Reloading…**. If the computer is unreachable or still restarting, the page stays open with a message and you can retry.

Older iOS builds, including CezarBot 0.1.1 (10104), can return the same cached cockpit on every reload. Close and reopen the server from the app's **Devices** list to start a new cache check after the computer reconnects. If the banner persists, close and reopen CezarBot. Avoid **Forget**, which removes pairing and website data.

The reliable reload fix requires an iOS app update as well as the cockpit update: the old app's native relay cache controls which HTML a page reload receives. A server update alone cannot replace that native code. The separate **restart to finish** banner means the server process needs restarting; reloading the phone page does not restart the computer's service.

## Relay terms on the phone

A phone paired through the Cezar relay accepts the relay's terms once. Right after pairing, and the first time a server opens while the phone has not accepted them, the app shows **Accept the relay terms**: the Terms and Privacy Policy links, an **I accept** box and **Continue**. **Not now** opens the server anyway; after 48 hours the relay refuses the phone until it accepts, and the app shows the same sheet without **Not now**. Accepting reconnects at once, with no new pairing.

If Open Mercato suspends a computer's relay access, the app says so and stops trying; contact Open Mercato.
