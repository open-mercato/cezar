The worktree list shows linked tasks, directory sizes, last activity, and which worktrees can be reclaimed. Reclaim now removes directories past the count limit (**Keep last N worktrees**) and the age limit (**Reclaim idle worktrees after**). After confirming, check the cleanup script results. For the whole picture, including the disk guard and `cez worktrees`, see [Disk usage and worktrees](/docs/features/settings-and-projects/disk-usage).

## Where to find it

Project settings → Worktrees → Reclaim now

## How to use it

1. Check the tasks, sizes, and last activity.
2. Use Reclaim now for directories past the count or age limit.
3. Confirm and check the cleanup result.

> **Good to know**: Reclaim keeps branches. Delete removes both the directory and its branch.

> **Good to know**: A worktree a running cezar uses is marked **Protected** with the reason — the desktop app's selected version (a `cezar link` of that worktree), a cezar server or other `node` process started from inside it. Retention skips it without counting it toward the limit, and Delete is refused. It becomes eligible again once nothing runs from it.

> **Good to know**: A pinned task's worktree is never reclaimed automatically and does not count toward the limit. Unpin (or archive) the task to make it eligible again.

> **Good to know**: Tasks in review and waiting are reclaimed too once they pass the age limit (default 7 days). The diff keeps working, read from the kept branch. Opening a pull request and Continue restore the worktree.

## A reclaimed task's Changes tab

A reclaimed task's Changes tab shows the kept branch's committed changes, with a note saying the worktree is not on disk. Line comments still work on that diff: earlier comments stay on their lines, and you can add new ones and send them. Opening files in an editor, file context and the terminal come back once the worktree is restored.

Use **Restore worktree** in that note, or on the Files tab, to check the branch out again. The restored worktree is reclaimed again later like any other. If the branch was deleted in the meantime, the tab says so and there is nothing to restore.

> **Good to know**: Archiving a task also frees its worktree. The branch is kept.
