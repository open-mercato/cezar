Wait for CI waits for pull request checks to finish. Place it after a step that creates or identifies a PR, then set a timeout and polling interval. The green, red, timeout, and failed outputs handle each outcome.

## Where to find it

Workflows → Add node → Wait for CI

## How to use it

1. Add Wait for CI after a step that creates or identifies a PR.
2. Set the timeout and polling interval.
3. Connect green, red, timeout, and failed.

> **Good to know**: If the task has no PR, the workflow takes failed. Waiting does not occupy a `maxParallel` slot.

> **Good to know**: Wait for CI judges the commit the task's worktree is on when the node starts. It waits until the PR's head is that commit, so a push that has not landed yet never yields the previous head's result. A PR with merge conflicts takes failed at once (the node's `status` is `conflict`) instead of waiting for the timeout.
