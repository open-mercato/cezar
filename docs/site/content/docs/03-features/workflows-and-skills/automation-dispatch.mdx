The Dispatch switch lets an automated task create subtasks with cez task create. Beside it, set the maximum number of subtasks and the review child option.

## Where to find it

Automations → editor → Dispatch

## How to use it

1. Enable Dispatch for the rule.
2. Set Max subtasks.
3. Optionally enable Review child and save the rule.

> **Good to know**: The setting is hidden if the server has disabled Dispatch. Subtasks work in their own worktrees and report results to the parent task.

> **Good to know**: Review child depends on Dispatch. Turning Dispatch off also turns Review child off, and re-enabling Dispatch leaves it off. If the server has disabled Dispatch, an automation saved with Review child launches as a plain task with no review instruction.

> **Good to know**: Dispatch off prevents the automated task from creating cezar subtasks, including when the prompt asks for subagents. The choice stays with the task through Continue and a server restart. Editing the rule later applies to new tasks. Tracker commands, automation commands and existing subtask reports remain available. Backend-native subagents and graph-workflow fan-out are separate from this switch.

Older automation tasks without a saved Dispatch choice need a recorded dispatch intent to create cezar subtasks. Otherwise, start a new task from the rule with Dispatch on. Ordinary tasks keep dispatch on by default.
