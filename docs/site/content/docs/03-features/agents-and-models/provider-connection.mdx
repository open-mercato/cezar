A provider card distinguishes missing installation, no connection, detected credentials, and failed checks. Connect starts the supported sign-in process; Check again repeats the check.

An agent that is not ready offers its next step right on its row, in the Providers card and in the default-agent picker. **Install** shows the exact command, runs it in a terminal in the sheet, and then moves on to the sign-in. **How to install** shows the command to copy and the vendor's docs when cezar does not run that installer itself. **Update** runs the update for the way the CLI was installed: Homebrew for a Homebrew install, npm for an npm one, the CLI's own updater otherwise. A chip beside the version says when a newer release exists, or when the installed one is older than a version the agent has said it needs.

## Where to find it

Settings → project → Agents → Providers

## How to use it

1. Find the provider and read its status.
2. If it is Not connected, choose Connect and finish signing in.
3. Return to Cezar and choose Check again.
4. For an agent that is not installed or is out of date, choose Install or Update, read the command, and confirm.

> **Good to know**: If Cezar cannot open a local terminal, it provides a command to run manually. Detected credentials do not guarantee available account quota.

> **Good to know**: cezar runs only installers it has checked against the vendor's docs or already shipped: Claude Code, Codex, OpenCode, Cursor and GitHub Copilot CLI. Gemini CLI, pi, Junie, Kimi Code and Antigravity show their command or docs to copy for now, and OMP always does, because it installs from a third-party Homebrew tap. While tasks run on an agent, Update waits for them unless you choose Update now. From a paired phone you can start an install or update that needs no password; the terminal is read-only there, and a sign-in that needs a terminal finishes on your computer. `CEZ_AGENT_VERSION_CHECK=0` turns off the newest-release lookup.
