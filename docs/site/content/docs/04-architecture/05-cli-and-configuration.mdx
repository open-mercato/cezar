## Starting Cezar from a terminal

Cezar requires Node.js 20 or later. Start it in your project directory. The package includes a built browser interface. Agent tools must be installed and signed in on the same machine. Cezar uses gh for GitHub integrations.

The default command is serve. The server listens on 127.0.0.1, normally on port 4321. If that port is busy, read the actual address from the cockpit → message. Use --repo to select another directory and --no-open to prevent the browser from opening automatically.

```bash
cd /path/to/project
npx cezar-run --no-open

# Show help without starting a task
npx cezar-run --help

# Specify a directory and port
npx cezar-run serve --repo /path/to/project --port 4321 --no-open
```

## Local commands and server commands

| Command | What it does |
| --- | --- |
| `cezar run` "&lt;task>" --workflow quick-task | Runs a workflow without a server or browser. It executes agent work, which can change files and consume provider quota. `--model` overrides the model, and `--effort` the reasoning effort of a Codex or Claude run; any other runner refuses `--effort`. |
| cezar projects / projects add &lt;directory> | Reads or changes the local project registry. No server is required. |
| cezar runs list --json | Reads tasks from the running server specified by `CEZ_API_URL`. |
| `cezar task` / `cezar automation` | Controls dispatch and automations on the running server. |
| `cezar worktrees` list / reclaim / prune / remove | Lists task worktrees and frees their disk. Uses the running server for the project when there is one, otherwise works on the project directory. |
| `cezar versions prune` [--keep N] [--dry-run] [--backups] | Deletes old installed versions; `versions.backup-*` folders only with `--backups`. |
| `cezar init` | Adds an example workflow and skill without overwriting existing files. |
| cezar install / update / versions | Installs or updates the managed launcher, or lists installed versions. |

> **Good to know**: cezar, cez, cezar-cli, and cezar-run are names for the same program in the package. Examples using cezar alone assume it is installed in PATH. Otherwise, use `npx cezar-run`.

## Connecting the CLI to a specific project

Commands that connect to the server require `CEZ_API_URL`. Without it, the CLI exits with code 2. Set `CEZ_PROJECT_ID` to select a project. If it is unset, the command applies to the directory where the server started. Use projects to read project IDs.

```bash
export CEZ_API_URL=http://127.0.0.1:4321
export CEZ_PROJECT_ID=project-id
npx cezar-run runs list --status running,review --json
```

## Where configuration is stored

Use `CEZ_HOME` to select a directory other than `~/.cezar`. This does not move repositories or their `.ai/cezar/` directories. Cezar does not automatically load a repository `.env` file. Required variables must be present in the process environment when it starts.

| Path | Contents |
| --- | --- |
| &lt;repo>/`.ai/cezar/config.json` | Optional project settings: runner, models, branch, worktree retention count and age, and instructions. |
| `~/.cezar/`config.json | Project registry and resources: concurrency limit, memory limits, monitoring settings, worktree age default, archived-task lifetime, and disk guard. |
| &lt;repo>/`.ai/cezar/workflows/` and skills/ | YAML workflows and local instructions. These can be tracked in Git. |
| &lt;repo>/`.ai/cezar/runs.json` and runs/\*.ndjson | Task index and event records. This working data is excluded from Git. |
| `~/.cezar/`agent-`accounts.json` | Additional agent accounts and the selected account for each project. |
| `~/.cezar/`tracker-connections/ | Managed tracker connection data. |

## Limits and default settings

Global `maxParallel` defaults to 2 and accepts values from 1 to 16. `memoryLimitMb` limits the memory of the entire task process tree; null disables that limit. Both fields belong to resources in the global `config.json`. Change them in Settings → Resources without replacing the whole file, which also contains the project registry.

The example below is part of an optional project configuration. `reviewGate` is disabled by default. Setting it to true makes non-autonomous tasks wait for a review of their changes, but does not block Git commands run by the agent. Working in the current directory (in-place) with landing: auto is a separate mode.

```json
{
  "defaultRunner": "codex",
  "baseBranch": "main",
  "worktreeRetention": 10,
  "reviewGate": true
}
```

`bypassPermissions` is also disabled by default. Setting it to true (Settings → Agents → **Skip all permission prompts**) runs the project's Claude Code tasks with `--permission-mode bypassPermissions`: every tool call is approved without asking, including commands outside the Claude Code Bash sandbox. Read-only tasks and a manager's own turns are never affected. cezar ignores the key while `.ai/cezar/config.json` is tracked by git, so a cloned repository cannot turn approvals off, and while it runs as root, because Claude Code refuses bypass mode for root. It is local-only: a hosted cockpit refuses to turn it on and ignores it.

## Worktree disk limits

Each task worktree is a full checkout. Reclaiming one removes the directory only; the branch stays and Continue restores it. A worktree with uncommitted changes is never reclaimed.

| Key | File | Default | Meaning |
| --- | --- | --- | --- |
| `worktreeRetention` | project | 10 | Keep the last N done, failed or cancelled worktrees. `0` = unlimited. |
| `worktreeIdleDays` | project | inherits | Reclaim a worktree of a task in review, waiting, done, failed or cancelled after N days without activity. `0` = off. Unset inherits the global default. |
| `resources.worktreeIdleDaysDefault` | global | 7 | Age limit for projects that set none. |
| `resources.diskGuard.minFreePercent` | global | 10 | The guard acts below the smaller of this percentage and `minFreeGb` of free space. `0` = off. |
| `resources.diskGuard.minFreeGb` | global | 5 | See above. `0` = off. |
| `resources.diskGuard.maxWorktreesGb` | global | 20 | The guard acts when worktrees of every project total more than this. `0` = off. |
| `archivedTaskDeleteDays` | project | inherits | Delete a task N days after it was archived, with its worktree and branch. A branch with an open pull request, or with commits neither merged nor pushed, is kept. `0` = never. Unset inherits the global default. |
| `resources.archivedTaskDeleteDaysDefault` | global | 90 | Archived-task lifetime for projects that set none. |
| `versionRetention` | global | 3 | Installed versions kept in `~/.cezar/versions`, the running one included. `0` = no automatic pruning. |

Edit them in Project settings → Worktrees and Settings → Resources → Worktrees. To free space from a terminal:

```bash title="Terminal"
npx cezar-run worktrees list
npx cezar-run worktrees reclaim --older-than 7d --dry-run
npx cezar-run worktrees reclaim --all-inactive
npx cezar-run worktrees prune
npx cezar-run worktrees prune --archived-older-than 90d --dry-run
npx cezar-run worktrees remove <runId>
```

See [Disk usage and worktrees](/docs/features/settings-and-projects/disk-usage) for what each mechanism covers and a manual cleanup on a server.

> **Good to know**: Set `baseBranch` to the correct branch for the repository. Missing or invalid configuration usually falls back to defaults. Configured lifecycle transitions have separate, strict validation.
